# CLASIFICACIÓN VISUAL CORRECTA

Corrige cualquier lógica equivalente a:

```ts
const detected = verdict !== "clear";
```

Implementa estados explícitos:

```ts
type VisualVerdict =
  | "clear"
  | "insufficient_evidence"
  | "review_required"
  | "suspected_device"
  | "confirmed_device";
```

Reglas:

* `clear`: no crear hallazgo.
* `insufficient_evidence`: solicitar nueva captura.
* `review_required`: crear observación informativa, no alerta.
* `suspected_device`: crear hallazgo pendiente de corroboración.
* `confirmed_device`: solo permitido cuando existen evidencias suficientes y consistentes.

Para elevar a `suspected_device`, exigir:

* Confianza por encima de un umbral configurable.
* Región concreta dentro de la imagen.
* Categoría identificable.
* Explicación basada en rasgos observables.
* Calidad mínima de imagen.
* Ausencia de blur severo.
* Exposición aceptable.
* Segunda captura desde otro ángulo.
* Consistencia entre ambas capturas.

Para elevar a `confirmed_device`, exigir corroboración adicional, por ejemplo:

* Coincidencia visual repetida.
* Evidencia de red o BLE compatible.
* Inspección manual validada.
* Captura cercana que muestre componentes físicos compatibles.

Nunca conviertas una respuesta ambigua del modelo en “ANOMALÍA DETECTADA”.
